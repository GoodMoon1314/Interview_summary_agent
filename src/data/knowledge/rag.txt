1. RAG 是什么？为什么需要 RAG 常见面试问题：为什么不让 LLM 直接回答，非要用 RAG？LLM 的知识截止问题你怎么解决？

LLM 的三大知识缺陷 第一，知识截止。训练数据存在截止日期，模型不知道截止时间之后发生的事情，遇到新发布的工具框架，要么编造内容，要么回答不知道。 第二，私有数据无法触达。公司内部文档、客户数据、业务规则没有参与模型训练，直接提问会输出胡说八道的内容。 第三，容易幻觉。模型不确定答案，但依然会输出回答，生成看起来合理实际完全错误的信息，缺少外部知识校验时幻觉问题会更严重。

RAG 核心思路 RAG 全称 Retrieval‑Augmented Generation，检索增强生成。核心逻辑是在大模型生成回答之前，先去外部知识库检索相关信息，把检索到的内容放到提示词里，让大模型依托真实事实来输出答案。

没有 RAG 的流程：用户问题直接送入 LLM，输出回答，存在幻觉风险。 使用 RAG 的流程：接收用户问题，检索外部知识库获取相关资料，把用户问题和检索到的资料一起送入 LLM，模型基于事实输出回答。

关键点：RAG 不会替代大模型，作用是补充外部知识。大模型负责理解问题与文本生成，RAG 负责提供事实素材。

1. RAG 完整链路 常见面试问题：做过 RAG 项目，请描述从用户提问到输出回答的完整链路。

RAG 完整七步链路依次为：Query 用户查询、文档处理、Chunking 文本切分、Embedding 向量化、检索、Rerank 重排序、生成回答。

文档处理步骤：解析 PDF、Word、Markdown 等各类文档，提取文档内文本内容。需要考虑的关键问题：PDF 当中的表格如何解析，是否需要开启 OCR 识别图片内文字。 Chunking 文本切分步骤：把长篇文档切割成较小的文本片段。关键考量：切片大小设置，切片之间重叠 overlap 数值，选择固定长度切割还是语义切割。 Embedding 向量化步骤：把每一段文本片段转换为向量表示。关键考量：选用哪一个向量化模型，向量维度大小，适配中文还是英文场景。 检索步骤：根据用户输入的查询，召回相关性高的文本片段。关键考量：使用纯向量检索还是混合检索策略，Top‑K 返回候选数量设置。 Rerank 重排序步骤：对已经召回得到的候选片段重新做相关性排序。关键考量：重排序模型选择，重排完成之后保留多少条结果。 生成步骤：将用户原始问题加上检索得到的参考片段一起输入大模型，生成最终回复。关键考量：提示词如何编写，如何约束幻觉问题。

面试回答要点：不只是罗列步骤，要讲清楚每一步做决策的理由，不只是说使用了什么工具，要说明为什么选择该工具，参数设置背后的考量。

1. 向量检索原理 常见面试问题：向量检索和关键词检索有什么区别？Embedding 的原理是什么，为什么语义相似的文本向量距离近？

向量检索本质：将文本转化成高维空间当中的向量点，语义越接近的文本，在高维向量空间当中距离越近。检索操作本质就是找出和用户问题向量距离最近的一批文档向量。

相似度计算普遍采用余弦相似度。余弦相似度计算向量夹角的余弦，取值范围从 - 1 到 1，数值越大代表两段文本相似度越高。数值等于 1 代表向量方向完全一致，0 代表完全无关，-1 代表方向完全相反。 优先选择余弦相似度，而不用欧氏距离的原因：欧氏距离会被文本长度影响，长文本向量模长更大，但是语义不一定相关。余弦相似度只对比向量方向，不受文本长短干扰，更适合语义检索。

ANN 近似最近邻检索：当文档数量达到百万级别，逐个全部计算向量相似度速度太慢。ANN 的思路是放弃寻找绝对最相近的向量，牺牲一小部分精度换取查询速度，返回足够接近的结果。

主流 ANN 算法： HNSW，多层跳表图结构，上层粗略搜索，下层精细搜索。查询速度快，内存消耗比较大，是 Milvus 向量库的默认索引。 IVF，先对向量做聚类，查询的时候只搜索距离查询向量最近的少量聚类簇。精度可控，适合超大规模的数据量。 PQ 乘积量化，对向量做压缩降低向量存储维度，节省内存开销，但是会损失一部分检索精度。

面试加分知识点：HNSW 有两个重要参数，ef_construction 是建图阶段搜索宽度，数值越大索引质量越高，但是构建索引速度变慢；M 代表每个节点的邻居数量，数值越大索引图越密集，内存占用也随之提升。

1. 向量数据库选型 常见面试问题：项目中使用的什么向量数据库，为什么选择它？

FAISS 属于程序库，不是独立服务，直接嵌入业务进程运行，没有原生持久化能力，需要自己实现持久化逻辑。适合百万规模以内向量，原型验证、Demo 开发，运维成本低，不适合大规模线上生产。

Milvus 是完整向量数据库，独立服务部署，支持分布式集群，原生支持持久化。支持亿级向量规模，面向大规模线上生产环境，缺点是运维成本中等，需要维护集群。

Qdrant 为独立向量数据库，原生持久化，部署轻量，可以单节点起步。适合千万级向量，中小规模生产场景，运维成本较低。

面试回答思路：说明自己项目选型的理由，同时讲清楚其他方案优缺点。举例：生产环境选用 Milvus，因为业务需要分布式多副本、原生持久化，FAISS 不支持分布式，Qdrant 当时生态不够完善；如果只是快速做 Demo，会优先使用 FAISS。

1. 纯向量检索缺陷与混合检索 常见面试问题：项目是纯向量检索还是混合检索，为什么？

纯向量检索存在三处致命缺陷。 第一，精确匹配能力不足。比如搜索特定编号 RFC 7231，向量检索会返回语义相关内容，但是不一定包含这个精确编号，语义匹配代替不了字面精确命中。 第二，专业术语召回效果差。像 K8s 的 HPA 这类缩写专业词汇，向量检索容易返回语义等价的通俗描述，丢失包含专业术语配置细节的文档。 第三，专有名词容易遗漏，产品名称、人名、缩写这类实体，纯向量检索很容易漏召回。

混合检索等于向量检索叠加 BM25 关键词检索。两路同时执行检索。向量检索负责抓取语义相关的文档；BM25 关键词检索实现字面、专有名词精确命中。之后合并两路返回结果，互相弥补短板。

结果合并常用 RRF reciprocal rank fusion 倒数排名融合。核心逻辑依据文档在每一路检索返回结果当中的排名计算分数，排名越靠前得分越高，k 一般设置为 60。不需要手动设置向量和关键词的权重，依靠排名自动融合，线上生产环境稳定性更好。

面试核心：讲明白纯向量检索的三个缺点，混合检索如何解决，以及 RRF 合并策略。

1. Rerank 重排序 常见面试问题：已经使用混合检索，为什么还需要 Rerank 重排序？

检索属于粗筛选，从海量文档里面快速取出候选集合，例如取出 Top‑20。依靠向量相似度、BM25 打分，速度快，但是相关性打分只是近似结果，准确度有限。 Rerank 是精细排序，针对粗筛得到的少量候选文档，使用精度更高的 Cross‑Encoder 模型逐个计算用户问题和文档片段的真实相关性，重新排序，把真正高度相关的内容放到靠前位置。

底层模型差异：检索阶段使用 Bi‑Encoder，问题和文档分开编码生成向量，编码过程互相看不到对方内容，只能做粗略相关性判断。 Rerank 使用 Cross‑Encoder，把用户问题和文档拼接在一起送入模型，模型同时阅读两者内容，可以做精准相关性判断。缺点是推理速度慢，不能预计算向量，只能处理少量候选，不能直接用来在全量知识库检索。

实际业务效果参考：没有 Rerank 的时候 Top‑5 召回率 71%，Rerank 之后提升到 89%；Top‑3 准确率从 65% 提升至 84%。

常用开源 Rerank 模型： BGE‑Reranker 系列，中文效果优秀，开源免费； bce‑reranker‑base_v1，面向中文，轻量级； Cohere Rerank，API 调用方式，英文表现好。

面试回答话术：检索做粗筛快速捞取一批候选，Rerank 做精排提升准确度。Bi‑Encoder 快但是粗略，Cross‑Encoder 精准但是速度慢。标准流程：先用检索取出 Top‑20，再经过 Rerank 重排，保留 Top‑5 送入后续生成阶段。

1. Chunk 文本切片策略 常见面试问题：项目的切片策略是什么，chunk size 设置多大，为什么？

切片设置过大带来的问题：信息稀释。单个切片包含大量无关内容，真正相关信息被淹没，向量相似度分数降低，文档排名靠后。 切片设置过小带来的问题：上下文丢失，完整的论述逻辑被切割打散，检索拿到碎片化片段，大模型无法理解完整语义，生成回复质量下降。

三种主流切片策略： 第一种固定长度切分，简单直接，按固定 token 数量切割。缺点不关注语义边界，有可能把完整一句话从中间切开。 第二种递归字符切分，优先按照段落、句子、标点顺序切割，尽可能在自然语义边界断开，是线上项目最常选用的方案。可以配置 chunk_size，同时设置 overlap 重叠大小。 第三种语义切分，依靠 embedding 计算相邻句子语义相似度，在语义发生变化的位置切割。理论效果最好，但是计算开销大，线上生产环境较少使用。

overlap 切片重叠的作用：相邻切片保留一小段重复文本，防止关键信息刚好落在切割边界被截断丢失。一般 overlap 取 chunk_size 的百分之十到百分之二十。

不同文档处理方案： Markdown 文档：按照标题层级进行切分，保留标题层级信息； PDF 文档：优先解析表格、图片，再做段落切分； 代码文件：按照函数、类为单位切分，保证代码块完整； FAQ 问答文档：一条问答完整作为一个切片，不要拆开问答对。

面试关键点：能够权衡切片大小的利弊，讲清楚 overlap 的作用，最好可以结合调参经验举例。

1. Embedding 向量化模型选型 常见面试问题：项目使用什么 Embedding 模型，为什么，对比 OpenAI ada‑002 效果如何？

选型主要看三个维度：语言适配能力、向量维度、MTEB 评测榜单检索效果。

中文常用模型： bge‑large‑zh‑v1.5，维度 1024，中文检索效果优秀，开源支持本地部署； bge‑m3，维度 1024，多语言，同时支持稠密向量、稀疏向量多种检索模式； OpenAI text‑embedding‑3‑large，维度 3072，整体效果好，但是调用 API 有成本，中文表现弱于 bge 系列； OpenAI text‑embedding‑3‑small，维度 1536，成本低，够用，更加适合英文业务。

向量维度不是越高越好。维度越高语义表达能力越强，但是存储、检索开销同步上涨。1024 维是性价比很高的选择，3072 维带来效果提升有限，但是存储开销扩大三倍。

面试回答示例：中文业务场景选用 bge‑large‑zh，MTEB 中文评测指标表现优秀，开源可以本地部署，不需要依赖第三方 API；英文业务或者对部署成本不敏感，可以选择 OpenAI Embedding。

1. RAG 幻觉问题处理 常见面试问题：检索拿到正确资料，大模型依旧编造虚假信息，该怎么处理？

幻觉分为两类： 内在幻觉：参考资料信息正确，但是模型输出内容和参考资料互相矛盾，例如参考写准确率 91%，模型输出写成 95%。 外在幻觉：模型生成参考资料完全不存在的全新信息，凭空编造事实。

六种处理幻觉的策略： 第一，提示词约束。在 Prompt 明确告知模型，只能够使用参考资料内容作答，资料没有的内容禁止编造。 第二，输出自校验。模型生成回答完成之后，再次调用大模型校验输出内容，检查每一条陈述是否都可以在参考文档找到依据，找不到就标记未验证。 第三，引用标注。要求模型输出回答的时候标注信息来源切片，方便人工核对溯源。 第四，调低生成温度 temperature，设置 0.1‑0.3，降低模型随机性，减少编造倾向。 第五，回答‑参考对齐校验。生成回答后，计算回答片段和检索参考片段相似度，如果大段内容和全部参考都不相似，判定大概率属于幻觉。 第六，兜底策略。当检索返回所有片段相似度全部低于设置阈值，直接回复未找到相关信息，不让大模型强行编造答案。

面试回答要点：不要只说使用提示词约束，要说明多种策略组合使用，可以举例说明优化前后幻觉率变化。

1. RAG 检索效果差的优化手段 常见面试问题：RAG 检索准确率多少，效果不好如何优化？

优化沿着整条链路逐个排查。 文档处理环节：PDF 表格解析准确率，图片文字是否做 OCR，不同格式文档是否做适配。 Chunk 切片环节：切片大小是否合适，针对不同文档是否调参，overlap 数值是否合理。 检索环节：是否采用混合检索，Top‑K 参数，是否开启 Rerank 重排序。 生成环节：提示词模板编写，幻觉约束方案。

四类高级优化手段： 第一，Query 查询改写。用户原始问题简短模糊，调用 LLM 把用户问句改写为更适合检索的查询语句。 第二，多路召回。同一个原始问题，使用原始 query、改写之后 query、提取关键词、拆解子问题，多路分别检索，把所有结果合并。 第三，父子检索 Parent‑Child。使用小尺寸切片做向量索引用于检索，小切片关联对应的完整大父切片；检索命中小切片之后，返回完整父切片，兼顾检索精准度和上下文完整。 第四，上下文窗口扩展。命中一个切片之后，同时取出该切片前后相邻的切片，保证上下文信息完整。

面试加分：结合自己项目，说出优化手段带来量化指标变化，例如开启 Rerank，Top‑5 召回率从 71% 提升到 89%；开启混合检索，专业术语场景准确率提升百分之二十五。

1. Agentic RAG 常见面试问题：了解 Agentic RAG 吗，和普通 RAG 区别？

普通 RAG 局限：属于固定流水线，用户提问之后执行一次检索，直接生成答案。第一次检索结果质量差，不会自动修正，直接基于差的结果输出回复。

Agentic RAG 把 Agent 智能体规划能力引入 RAG。交给大模型自主判断，需要检索哪些数据源，现有检索资料够不够回答问题；资料不足就修改查询条件再次检索。

普通 RAG 特点：检索次数固定只有一次；检索策略写死在流程；检索结果不理想依旧直接生成；复杂问题容易回答跑偏；token 消耗低。 Agentic RAG 特点：检索次数动态变化，由大模型自主决定；检索策略由模型动态选择；结果不足会重新检索；可以拆解复杂问题，分步检索子问题；token 消耗更高，存在多次大模型推理。

Agentic RAG 执行流程：接收用户问题，Agent 做任务规划，确定需要检索的内容；执行第一次检索；大模型判断现有资料是否充足；如果不足，修改查询条件再次检索；确认资料足够之后，生成最终回答。

面试判断要点：Agentic RAG 适合法律、金融这类复杂知识问答；简单问答场景直接使用普通 RAG 即可，不要过度设计。 还有一部分复杂问题，普通 RAG 和 Agentic RAG 都很难处理，比如实体复杂关联、多跳推理，这种场景可以引入知识图谱方案 GraphRAG。

1. RAG 面试高频追问 --- 检索策略类 问题：混合检索当中向量检索和 BM25 权重如何调节？ 回答：方案一，手动设置权重，例如向量 0.7，BM25 占 0.3，在验证集调试最优数值。方案二使用 RRF 倒数排名融合，不需要设置固定权重，依靠排名融合，线上更加稳定。推荐 RRF，不同查询语句最优权重不一样，固定权重泛化能力差。

问题：Top‑K 参数设置多少，设置太大太小分别会有什么问题？ 回答：K 设置过小，例如等于 3，会漏掉相关文档，召回不足。K 设置过大，例如 20，引入大量无关片段，干扰大模型，增加幻觉风险，同时消耗更多 token。一般 5‑10 是平衡点。开启 Rerank 场景，可以检索取 Top‑20，重排序之后保留 Top‑5。

问题：用户提问模糊，检索效果差怎么办？ 回答：做 query 改写，大模型把模糊问句改写明确；多路召回，原始问句、改写问句、关键词分别检索合并；也可以像 Agent 一样主动追问用户，把问题澄清。

--- 工程落地类 问题：端到端延迟如何优化？ 回答：使用 vLLM 部署大模型推理服务，降低推理耗时；复用 KV Cache，重复或者相似查询减少计算；开启流式输出，用户不用等待全部生成完毕；压缩 Prompt，降低 token 数量；向量库优化 HNSW 索引，把检索延迟压到 50 毫秒以内。

问题：文档更新，向量索引如何更新？ 回答：全量重建，实现简单，更新速度慢，适合按天更新场景；增量更新，只重新向量化发生变更的文档，适合实时更新；双写方案，新文档同时写入新旧两套索引，切换索引实现零停机。

问题：如何控制 token 成本？ 回答：压缩 Prompt，裁剪检索片段冗余内容；上下文窗口管理，只保留和当前问题相关历史对话；模型路由，简单问题调用小模型，复杂问题调用大模型；缓存热点查询的检索结果，重复查询直接复用。

--- 系统设计类 问题：设计面向十万用户的 RAG 知识库系统。 回答：数据层，文档解析、切片、向量化；向量库和 ES 搜索引擎双写保存数据。 检索层，混合检索搭配 Rerank 重排序，检索取 Top‑20，重排输出 Top‑5。 生成层，vLLM 部署推理服务，配置 Prompt 模板，增加幻觉约束逻辑。 工程层，Redis 缓存高频查询；文档更新采用异步任务；监控指标包含检索召回率、幻觉率。 安全层，文档权限隔离；防御提示词注入攻击；过滤敏感信息。

FAQ 汇总 Q：RAG 是什么？为什么需要 RAG？ A：RAG 检索增强生成，大模型生成前从外部知识库检索资料放入 Prompt，让模型基于事实回答。解决大模型知识截止、私有数据不可访问、模型幻觉三大问题。

Q：纯向量检索存在什么问题，为什么要用混合检索？ A：纯向量依靠语义相似度，专有名词、专业术语、精确编号召回效果差。混合检索同时运行向量检索和 BM25 关键词检索，RRF 融合两路结果，是线上主流方案。

Q：Rerank 是什么，检索之后为什么要重排序？ A：检索用 Bi‑Encoder 速度快但是结果粗糙；Rerank 使用 Cross‑Encoder 拼接问题和文档做精细相关性打分。标准流程，检索粗筛拿到 Top‑20，Rerank 精排选出 Top‑5。

Q：RAG 幻觉怎么处理？ A：多种策略叠加使用。Prompt 约束仅参考文档作答；输出自校验；信息引用标注；调低 temperature；校验回答与参考相似度；相似度不足直接兜底回复未找到信息。单一策略效果有限。

Q：RAG 和微调如何选择？ A：RAG 适合知识经常变动、回答需要溯源的业务场景。微调适合固化领域能力、改变模型输出风格。大部分业务优先使用 RAG，确实需要再做微调，两者也可以结合使用。
